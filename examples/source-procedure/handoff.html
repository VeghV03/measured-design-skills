What this is

The File Manager redesign has two audiences and therefore two documents, and the project rule is that both stay current or neither is trusted:

  • The BizDev canvas (Google Doc 1-nvpA2OER…EQtmHs) — the agreed scope. Journeys, step IDs and gates live there and are copied into the prototype without paraphrase, so a name means the same thing in both.
  • The prototype — every screen, with the reasoning, the routes, the failure states and the product IA. This is what engineering and QA build from.

Everything in the prototype is generated from Python source. No screen is hand-authored HTML, no copy is typed twice, and the build refuses to complete if the route map and the boards disagree.

The one rule that shaped everything

Say the consequence in plain words; never the mechanism. A person is told that sharing cannot be taken back. They are never told about postage batches, chunks, ACT, feeds or dilution — those words appear only inside Advanced, and a build-time check counts them everywhere else. The count outside Advanced is 0.

The whole rebuild

Four commands, deterministic — re-running produces byte-identical files, which is how you know the published copy is still the current one:

  • for f in build*.py; do python3 $f; done — redraw all 93 boards
  • python3 proto.py — rebuild the prototype; refuses on a bad route map
  • python3 offline.py — rebuild the offline copy
  • sh sync-all.sh && sh seed-all.sh — stage and re-seed the six canvases

What the product decided

Forty-two decision records ride on the screens they govern, so a reviewer is never looking at a screen without its reasoning. The ones that shaped the most:

DecisionWhat it settles
r-plainwordsConsequence in plain words, mechanism never. Mechanism vocabulary outside Advanced: 158 → 0.
r-landingHome is a permanent landing page, not a dashboard. Reverses canvas E1, which is right for a product you live in and wrong for one you visit every few weeks.
r-provenanceSomething the product observed wears the inbound chip; something the user asserted is plain grey. Never "strong / weak evidence".
r-chips"Only you" is plain text; every other access state is a chip, graded by reach. Blue is revocable, amber is not — because with a public link the chunks are already fetchable.
r-forgetRemoving moves things to Removed, which still costs storage. The verb is "Remove", so the place is its past tense.
r-dragDropping is buying and says the size before you let go. Moving is not, and says so while you are still holding — everywhere else in software, dropping a file into a shared folder shares it.
r-waitThe purchase wall stays; the wait behind it becomes leaveable. The queued file is named, and the end of the wait comes and finds you.
r-emptyEvery user-facing place has its empty state drawn, from one shared component. Seven were missing; seven teams would have invented seven answers.

Open items

1 · The Google Doc is eleven edits behind

This is the only thing genuinely blocking handoff, because the doc is the other source of truth. Missing: gates G13, G14, JF1 (asserted in the artifact, never seen in the doc), the G11/G12 remedy fix, the S section, the rail decision, the A0/A1 password corrections, journey F, and now the two renames plus the gesture step-text changes.

2 · Six steps the canvas asks for that nothing draws

Recorded against their step IDs, so they read as scope gaps rather than a to-do list:

StepGap
A5 / A8Pre-save storage estimate for a file — the same gap from both ends. Websites show a cost before saving; files do not.
A3Two distinguishable upload-refusal causes. Only the partitioned-storage case is drawn, so a stamper that failed reads as storage never bought.
B7Stopping the public link — the site case, where every published version stays reachable by index at the same address.
C7The stop-sharing confirmation door. The list offers it and the aftermath is drawn; the screen between them is missing.
E5Choosing between two kept versions of one file.

3 · Two gaps the backlog found in us

  • No home page in the chosen folder. Falls under the documented trouble rule — the input is ambiguous and the product refuses to guess. Never auto-pick: a wrong home page publishes the wrong thing under a permanent address.
  • The scanning state between folder pick and modal. Nothing under 400ms; past that, name the folder and the count so far, because silence reads as a crash.

4 · One decision engineering must settle

The one-computer-at-a-time constraint (r-devices) is inferred from two documented facts, not from a documented two-node case. If devices are already coordinated, OtherComputer and TakeOver should be deleted rather than built.

5 · The widget has never been drawn alone

FM-1505 requires the File Manager to ship standalone. All 93 boards draw the full window — titlebar, rail, sidebar, content. If that requirement is real, it affects every board.

Picking this up

  1. Rebuild and verify first. Run the four commands above, then the harnesses. If proto.py refuses, it is telling you the route map and the boards disagree — fix that before anything else.
  2. Read the prototype's product view (press p) before the map. It answers "what kind of thing is this screen" for all 93, which is the question that makes the rest legible.
  3. Change copy in the generator, never in the HTML. The .dc.html files are build output and are overwritten.
  4. Add a screen in four places or the build will stop you: the generator, a journey step in journeys.py, an IA kind and title in proto.py, and a canvas artboard in canvases.py.
  5. Never bulk-edit copy with a regex across the generators. See the procedure document — this failed once, damaged five files, and the repair took longer than the rewrite.
